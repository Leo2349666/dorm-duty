你是一名资深全栈工程师兼产品经理。请帮我从零设计并实现一个“寝室值日排班系统”。请先输出需求分析、技术方案、数据模型、排班算法、页面结构，再输出完整可运行代码、数据库建表 SQL、GitHub Pages 部署步骤。要求代码结构清晰、注释完整、移动端优先、响应式适配、微信内可正常打开。

【项目背景】
寝室共 5 人，需要安排每天的值日。成员可以添加、删除、编辑。值日内容默认为：阳台、地面、倒垃圾、洗手台、浴室，共 5 项；值日内容可以自由添加、编辑、删除、排序。排班周期可以调整，默认一周 7 天。每人每个周期至少需要被分配到一项值日内容。

【核心目标】
做一个无需登录、打开链接即可使用的寝室值日排班网页。可部署到 GitHub Pages，部署后通过链接直接打开，微信内点击链接也能正常打开和使用。移动端和电脑端都要适配，移动端优先。支持多设备同步。

【技术栈与部署】
1. 前端：React + Vite + TypeScript + Tailwind CSS，使用 React Router 的 HashRouter，避免 GitHub Pages 刷新 404。
2. 状态管理：Zustand 或 React Context 均可。
3. 数据同步：使用 Supabase 或 Firebase 等免费 BaaS，实现匿名认证 + 房间共享。无需注册登录。房间唯一标识由“公寓 + 楼栋 + 房间号”组成。多设备输入相同公寓、楼栋、房间号即进入同一房间数据，并实时同步。
4. 如果必须纯静态无后端，则提供本地 localStorage 模式 + 导出/导入 JSON 作为降级方案，但明确说明纯静态无法真正多设备同步。
5. 部署：GitHub Pages + GitHub Actions，配置 Vite base 路径。确保微信内置浏览器可打开。
6. 不要求账号密码，不要求传统登录。

【功能需求】
1. 成员管理：默认 5 人，可添加、删除、编辑成员姓名、排序、启用/停用。删除成员后历史记录保留。
2. 值日内容管理：默认阳台、地面、倒垃圾、洗手台、浴室，可添加、编辑、删除、排序。
3. 排班周期设置：
   - 周期天数可调整，默认 7 天（一周）。
   - 可设置第一次排班的开始日期。
   - 可设置最后一周的结束日期。
   - 例如：周期一周，开始日期 2026-09-07，结束日期 2027-01-11。系统按此范围生成排班。
   - 若自定义天数，则周期长度和起止日期均可灵活调整。
4. 自动排班：一键生成从开始日期到结束日期的所有排班。
5. 手动调整：支持在日历视图中点击某天，调整当天值日人员与值日内容的对应关系。调整后记录到历史。可选择“仅本次调整”或“从本次起更新后续轮换基线”。
6. 日历视图：月视图和周视图，显示每天值日人员和内容，点击某天查看详情和编辑。
7. 历史记录：保存每次自动排班和手动调整记录，可查看过去排班、调整前后对比、操作时间。
8. 统计功能：统计每个人值日次数、每项值日内容被分配次数、公平度。
9. 导出功能：支持导出 JSON、CSV、图片或 PDF。
10. 今日值日：首页突出显示今天谁负责什么，可标记完成。
11. 多设备同步：同一房间（公寓+楼栋+房间号）下，多台设备实时同步成员、值日内容、排班、调整和历史。
12. 移动端底部导航：今日、日历、成员、内容、设置/历史。桌面端使用侧边栏。

【自动排班与轮换规则（重要）】
1. 轮换仅根据周期进行，没有每天轮换。周期内，同一项值日内容均为同一人负责；下一个周期才轮换人员。
2. 成员有一个固定顺序列表，可拖拽排序。
3. 值日内容有一个固定顺序列表，可拖拽排序。
4. 首次排班：按成员顺序依次对应值日内容顺序分配。例如成员顺序为 [甲, 乙, 丙, 丁, 戊]，值日内容顺序为 [阳台, 地面, 倒垃圾, 洗手台, 浴室]，则甲负责阳台，乙负责地面，丙负责倒垃圾，丁负责洗手台，戊负责浴室。
5. 下一个周期轮换：将成员顺序列表循环右移一位，再依次对应值日内容顺序。例如 3 人时，本次 [甲, 乙, 丙] 对应 [阳台, 地面, 倒垃圾]；下次成员顺序变为 [丙, 甲, 乙]，对应 [阳台, 地面, 倒垃圾]，即丙负责阳台，甲负责地面，乙负责倒垃圾。如此往复。
6. 周期内每天的值日安排相同。例如周期为一周，则本周 7 天每天都是甲阳台、乙地面、丙倒垃圾……直到下一周轮换。
7. 如果成员数小于值日项数，则剩余值日项按成员顺序循环继续分配，允许同一人负责多项。
8. 如果成员数大于值日项数，必须保证每人至少一项，允许同一值日项由多人共同负责，或提示用户增加值日项。
9. 支持手动调整，调整后记录历史，并可按设置决定是否影响后续自动轮换。
10. 生成排班时，从设置的开始日期起，按周期天数划分周期，直到结束日期。最后一个周期可能不足一个周期天数，按实际天数处理，人员对应关系沿用该周期的轮换结果。

【数据模型建议】
- rooms：id、apartment、building、room_number、name、period_days、start_date、end_date、rotation_mode、created_at，其中 (apartment, building, room_number) 唯一。
- members：id、room_id、name、order_index、active、created_at
- duty_items：id、room_id、name、order_index、created_at
- schedules：id、room_id、date、cycle_index、created_at
- assignments：id、schedule_id、member_id、duty_item_id、is_manual、note
- change_logs：id、room_id、schedule_id、action、before_json、after_json、created_at
